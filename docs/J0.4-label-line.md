# J0.4 — Function-key label line and CLS

**Gate: VA 41/41, VA2 41/41** on vaeg PR [#82](https://github.com/nakatamaho/vaeg/pull/82) (`m153`, `6367e5d3`), not main. Both match the NEC 3.3D default label order and positions. Hiding the line gives DOS a 25th text row; showing it restores the 24+1 split. Cost on both models: **320 bytes of conventional memory and one emulated frame to prompt**.

## Decisions and sources

- **80 columns × 25 visible rows on both models.** The baseline shows 20 rows. Use text BIOS `CrtCtl` `AX=2404h`: text on, 80 columns, 25 lines, non-interlaced, with the 200/400-line mode bit clear (`604TEXT.TXT` §6.4.3, function 34). This is the successful [J0.1 mode X](J0-probe.md#1-enable-the-line-scroll-dos-con-then-run-cls) mode and matches the NEC 25-row reference. J0.4 verified it with both models' ROM sets. `Allocfb` reserves a full 25-row main buffer plus a separate, non-overlapping one-row system buffer. `Spltscn` displays the first 24 main rows and the system row; wrap and vertical scroll are enabled only on the main screen (functions 26–27).
- **`ESC[>1h` expands to 25 text rows without clearing existing text.** On NEC MS-DOS 3.3D in NP2kai, `LABELCHK P` [kept text on hide](J0.4/nec-hide.png); after 30 numbered lines, [#07–#30 occupied rows 1–24 with the cursor on row 25](J0.4/nec-scroll.png). On show, [#08–#30 occupied rows 1–23](J0.4/nec-show.png) and the cursor moved to row 24 above the labels. The VA text BIOS can do the same without copying or clearing the main text: turn off `SftCtl`, switch to a 25-row view of the same buffer, blank only the newly exposed row, and restore the cursor (`Askloc`/`Locate`). On show, scroll once with `Index` if the cursor is on row 25, shrink the view and re-enable `SftCtl`. A split resets the BIOS cursor tables, so saving and restoring the position matters (`604TEXT.TXT` §6.4.3, functions 7, 12, 22, 27, 36, 43). The tested bottom-row reflow matched NEC on both models; no blank-only fallback needed.
- **Only the ROM draws the labels.** At boot VAIO calls `ExpCtrl` with expansion off and passes all 31 slots of the existing CON table to `DefSft` (`603KEYB.TXT` §6.3, functions 3–4; use the BNN manual's ES:DX convention verified in [J0.1 §2](J0-probe.md#2-which-bytes-appear-as-the-label)). `SftCtl` `AX=2F0Ah` selects ten shift-aware labels. Default boxes match [NEC's order, widths and column starts](J0.4/nec-prompt.png); font pixels need not be identical. On VA/VA2 the ROM shows the first six bytes of the Shift definitions, including a CR glyph after `date` and `time`. CON input still uses the [J0.3 primitive queue and VAIO table](J0.3-fkeys-input.md), including the existing `FEh` prefix skip on input.
- **CLS and CON escape handling.** The CON attribute (`8003h`) is unchanged. As in [J0.1 §1](J0-probe.md#1-enable-the-line-scroll-dos-con-then-run-cls), COMMAND uses an ordinary handle write for this CON. VAIO now recognizes just `ESC[>1h`, `ESC[>1l`, `ESC[2J`, `ESC[H` across requests. `Erascn` clears the current text area without moving its cursor; `Locate` homes it separately (`604TEXT.TXT` §6.4.3 functions 21 and 7). A prefix is held while it can still match; a mismatch replays the buffered printable bytes under the old filter (ESC dropped) and reprocesses the mismatching byte. File redirection bypasses CON and keeps all seven bytes. No COMMAND, kernel, CON attribute, B1 stack-switch or keyboard path changes; no INT 10h calls added.
- **Native escape probe (not used by the implementation).** The technical manual documents escape interpretation for `Putstr` and `Chuput` (§6.4.3, functions 1 and 3). `LABELCHK U` and `V` bypassed DOS CON and tried all four sequences on each model. Neither BIOS entry hid or changed the labels with `ESC[>1h`/`ESC[>1l` in this mode. Both cleared only the main screen on `ESC[2J` and moved the cursor to row 1, column 1 on `ESC[H` (verified by the `HOME` marker). See [VA](J0.4/va-native.png), [VA2](J0.4/va2-native.png) and [observations](J0.4/observations.txt).

## Gate results

Counts are checks, not unique boots. Pass criteria and evidence are the same for both models. See the [decoded observations and extracted bytes](J0.4/observations.txt), [VA display](J0.4/va-display.png), [VA2 display](J0.4/va2-display.png), [VA toggle](J0.4/va-toggle.png), [VA2 toggle](J0.4/va2-toggle.png), [VA input](J0.4/va-input.png) and [VA2 input](J0.4/va2-input.png).

| 5. Hide/show | 3/3 | 3/3 | One pair via INT 21h/40h, one pair via 02h single-byte calls, and `P` comparing hidden scrolling/reveal with NEC. Main text retained on hide; row 25 available; bottom row restored. |

`LABELCHK F` additionally confirmed that unsupported sequences and a prefix followed by CR print their literal printable parts. Physical hardware, 2D media boots and emulator builds other than the named PR #82 build: **NOT RUN**. An early test-only build accidentally emitted a 386 conditional jump and halted in the probe; the counted runs used `cpu 8086` and verified that every script reached its final `exit` event.

| Model | CHKDSK free before → after | First prompt-ready frame before → after |
|---|---:|---:|
| VA | 532,480 → 532,160 B (**−320 B**) | 372 → 373 (**+1**) |
| VA2 | 532,480 → 532,160 B (**−320 B**) | 364 → 365 (**+1**) |

Boot time is the first `CISTAT` hit from reset, with no injected input, on the unmodified distribution disks. Screen/TVRAM at that breakpoint show the COMMAND prompt. Total memory was 655,360 B in all four CHKDSK runs. `RESEND` grew from `0AD4h` to `0C1Eh`: 330 bytes before paragraph rounding, 320 after. `IO.SYS` grew from 19,018 to 19,434 bytes and still occupies 19 boot sectors. `MSDOS.SYS` and `COMMAND.COM` compared byte-identical. See [assembly evidence](J0.4/build.txt).

## Reproduce

- **Builds:** Run the unmodified FreeDOS-88VA/freedos `experiments/msdos4-va/build.py` at `66a6acef778ae6aebe5a9d85219788972d6eef9d`, with emu2 `9d8698d06e67359bc8b230c2d19d5b1503e60819`. In two scratch locks set `msdos.commit` to `643d872` and `c12375d`, respectively, as in [J0.3](J0.3-fkeys-input.md#build-and-run). Distribution D88 SHA-256 values: `c4fcc9cb49ed37d33d194838b59b887dd324939ff873c4afc33d279bf2527fd3` (baseline) and `2ab09669fa63daddcd8949180b747d3a91978498820c8be834ec2b924b3e5ac1` (after).
- **VA test disk:** Assemble [`LABELCHK.NAS`](../tests/pc88va/LABELCHK.NAS) with `nasm -f bin -o "$SCRATCH/LABELCHK.COM" tests/pc88va/LABELCHK.NAS` (SHA-256 `59ca0cdce5e9db54f1ae022d48560b2fc8060f53d1b714b45474c59fde7f11a9`). Append `LABELCHK.COM`, `LONG.TXT`, `CONKEY.COM` in that order using the [J0.1 D88 reconstruction recipe](J0-probe.md#build-and-run). `LONG.TXT` is the ASCII string `TYPE LINE 01\r\n` through `TYPE LINE 40\r\n`; `CONKEY.COM` is the [J0.3 probe](J0.3-fkeys-input.md#build-and-run). Test D88 SHA-256 `5543599ae76d0baf532ccef2c40628a7a87a54bd3c4853ba8c2a145e516f5dc9`.
- **VA run:** Reused the [J0.3 PR #82 binary](J0.3-fkeys-input.md#build-and-run) (SHA-256 `a3ab65a03eac9fd2abccca3d51b8e464266a4b6141b9d5132b5b667495655906`). The runner makes a writable copy per cold boot and keeps its captures and event logs outside the repository:

  ```sh
  PYTHONPATH="$VAEG_SOURCE/tools/qa" python3 docs/J0.4/run-va.py \
    "$VAEG" "$VA_ROMS" "$BASE_D88" "$AFTER_D88" "$TEST_D88" "$SCRATCH/runs"
  ```

  Extract `F.TXT` from `display/disk.d88` and `T.TXT` from the four COPY CON images per model with the builder's `readfile.py`. The native and split-CLS marker checks use the TVRAM text captures; the label comparisons use the screenshots' bottom 16 guest pixels and the ROM system buffer's character words.
- **NEC:** Reused [J0.3b's NP2kai SDL2 build and PC-98 ROM setup](J0.3b-editing-keys.md#reproduce), commit `5939e0c6d5985c4c08fc70f289a83290e5d3e6f7`. In a scratch copy of its `DOS33D_1.D88`, put `LABELCHK.COM` in cluster 1222 as with the earlier `CONKEY.COM` (replace that root entry's name/size and the cluster payload if using the J0.3b probe disk). Pass the disk's **absolute path** to NP2kai in Xvfb; cancel INSTDOS with Escape, Return, then leave MENU with F9. At `A>`, run `labelchk p` and capture before the first and after each of the next three Space taps. No disk images, ROMs or extracted manuals are included.
