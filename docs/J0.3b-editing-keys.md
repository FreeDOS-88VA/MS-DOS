# J0.3b — Editing keys versus NEC MS-DOS

**Result: no fix needed.** J0.3 (`5f1f287`, tested on top of `97fadc8`) matches NEC MS-DOS 3.3D for the tested keys. On VA2, Backspace, LEFT, and DEL each erase both columns of a caret pair while removing exactly one byte. All tested caret lines could be submitted without hanging COMMAND. No VAIO, kernel, or COMMAND code changed.

## Per-key comparison

NEC runtime observations are from the [3.3D `A>` prompt](J0.3b/nec-version.png) in NP2kai ([before/after captures](J0.3b/nec-keys.png)). The maintainer's real PC-98 report also covers UP, RIGHT, and Backspace on `^K^K`. The NEC 3.3D *User's Guide*, p. 205, D.7–D.8 (PDF 219), documents Ctrl-H, Ctrl-J, and INS as F8. The byte column was checked independently using `CONKEY K` (DOS INT 21h/07h) on [NEC](J0.3b/nec-raw.png) and [VA2](J0.3b/va-raw.png).

| Key | NEC behavior and source | CON bytes on both | VA2 behavior before → after |
|---|---|---|---|
| UP | Echoes `^K`; `^K^K` + BS leaves `^K` (maintainer, emulator). | `0B` | Same → unchanged. |
| RIGHT | Echoes `^L`; `^L^L` + BS leaves `^L` (maintainer for echo, emulator for both). | `0C` | Same → unchanged. |
| DOWN | Screen-only newline. After `AB` + DOWN + BS, the old row still shows `AB`, but [F3 after Enter recalls only `A`](J0.3b/nec-down-recalled.png) (emulator; guide D.7 for Ctrl-J). | `0A` | Same visible old row; DOS 0Ah returns only `A` → unchanged. |
| LEFT | `AB` → `A`; then BS empties the line (emulator). | `08` | Same → unchanged. Also removes an entire caret pair. |
| HOME/CLR | Echoes `^Z`; BS removes one pair (emulator). | `1A` | Same → unchanged. |
| Shift+HOME/CLR | Echoes `^^`; BS removes one pair (emulator). | `1E` | Same → unchanged. |
| DEL | `AB` → `A`; then BS empties the line (emulator). | `1B 44` | Same → unchanged. Also removes an entire caret pair. |
| INS | Enters insert mode. With template `ABCDEF`, `X`, INS, `Y`, BS leaves `X`; `Z`, F3 yields [`XZBCDEF`](J0.3b/nec-ins-recalled.png) (emulator; guide D.8). | `1B 50` | Same → unchanged. |
| ROLL UP | No input or echo; after `AB`, BS still removes `B` (emulator). | none | Same → unchanged. |
| ROLL DOWN | No input or echo; after `AB`, BS still removes `B` (emulator). | none | Same → unchanged. |
| HELP | No input or echo; after `AB`, BS still removes `B` (emulator). | none | Same → unchanged. |
| Backspace | Removes a whole caret pair (`^K^K` → `^K`, maintainer and emulator); `A^KB^L` → `A^KB` (emulator). | `08` | Same → unchanged; one fewer byte in the DOS 0Ah buffer. |

The VA2 result agrees with the DOS code: `DBCS.SW` is `FALSE` in the tested build, so `CPMIO.ASM` includes `STRIN.ASM`. `SAVCH` stores one byte and echoes through `CPMIO2.ASM:BUFOUT`, which emits the two caret columns. `BackSpace` calls `BACKUP`, which decrements the byte count and buffer pointer and falls through to `BACKMES` to erase one column. For these control bytes, `BackSpace` calls `BACKMES` a second time without decrementing the count again. DEL's `ESC D` dispatch in `DOSMES.ASM` reaches the same `BackSp` entry as the `08h` keys. No difference required a change to that path or the VAIO table.

## Reproduce

**VA2:** Reused the [J0.3 image and emulator](J0.3-fkeys-input.md#build-and-run) after verifying both recorded SHA-256 values (D88 `c4fcc9cb…`, vaeg m153 `a3ab65a0…`). The VA `MSDOS.SYS` in the existing J0.3 base/after builds also matched by `cmp`. Assemble the test-only [EDBYTES.NAS](../tests/pc88va/EDBYTES.NAS) with `nasm -f bin ... -o EDBYTES.COM`; add it to a scratch copy as in [J0.1](J0-probe.md#build-and-run), substituting `EDBYTES` for `FKPROBE`. The COM SHA-256 is `5f4a7199a21b5d1dca47580e6c40bfe727c77f20a8e2402ae26b90ccba9e192c`; the test D88 SHA-256 is `98eccdf100666da9522fe48f9558fa28996d620854ba0a94108c61b7cf3fb575`.

```sh
PYTHONPATH="$VAEG_SOURCE/tools/qa" python3 docs/J0.3b/run-va.py \
  "$VAEG" "$VA_ROMS" "$J03_D88" "$EDBYTES_D88" "$SCRATCH/va"
```

The runner uses cold boots and real VA key make/break events. Its captures use the J0.3 `CISTAT` address `1000:059C` (the first instruction after the CON key table in `IO.SYS`); `EDBYTES` prints the actual returned count and contents, not the echo. The caret runs used the five no-erase controls and each physical eraser. The mixed and ordinary-letter cases were repeated with Shift held for uppercase; the table uses those runs. Earlier launcher attempts with unsupported frame-only `capture` commands are not counted. For the raw stream, use the J0.3 CONKEY image and [raw-va.debug](J0.3b/raw-va.debug) in the J0.3 invocation.

**NEC:** Built the unmodified SDL2 target of [NP2kai](https://github.com/AZO234/NP2kai) at `5939e0c6d5985c4c08fc70f289a83290e5d3e6f7`, outside the repository:

```sh
cmake -S np2kai -B np2-build -G Ninja -DUSE_SDL=2 -DBUILD_WX=OFF \
  -DUSE_NETWORK=OFF -DUSE_VST3SDK=OFF -DCMAKE_BUILD_TYPE=Release
cmake --build np2-build --target sdlnp21kai_sdl2 -j5
```

The first build was time-boxed at 240 seconds and resumed from the partial build; the resume completed. Used default machine settings with a scratch `$HOME/.config/sdlnp21kai` holding symlinks to the local PRIVATE PC-98 BIOS, font, ITF, and sound ROMs (lowercase filenames) and an IPA Gothic `default.ttf` for the host UI. Booted `DOS33D_1.D88` from the archive (SHA-256 `0879cb724de42da021f6adeab447597fcd2553efe421440fb63ae02bfd69907f`) in Xvfb with `SDL_AUDIODRIVER=dummy`. Cancelled INSTDOS with Escape, Return and exited MENU with F9. At the `A>` prompt, ran [run-nec.py](J0.3b/run-nec.py) with the X11 window ID. The emulator maps the host End key to HELP, Home to HOME/CLR, and Page Up/Down to ROLL UP/DOWN.

For `--raw`, booted a second scratch disk containing the same `CONKEY.COM` as J0.3. The only changes to the disk were allocating cluster 1222 in both FAT12 copies, adding the `CONKEY  COM` archive entry at the first unused root slot, and writing the 345-byte COM there in the data area. The original prompt tests did not use this modified disk. Both raw runs used ASCII digit delimiters to distinguish empty assignments. The result, including delimiters and without the final `q` that exits the probe, was:

```text
31 0B 32 0C 33 0A 34 08 35 1A 36 1E 37 1B 44 38 1B 50 39 30 31 32 08 33
```

No ROMs or disk images are included.
