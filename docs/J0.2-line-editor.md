# J0.2 — NEC line-editor keys

**Gate failed at step 5.** The VA2 build booted and passed steps 1–4. The `COPY CON` run timed out before it could verify EOF or `TYPE`. Steps 6–8 were not run after that failure. The non-PC88VA kernel comparison passed.

## Key choices

The distribution kernel uses `v4.0/src/DOS/MSSW.ASM` (included by `INC/MSDOSME.ASM` and `DOS/MSCTRLC.ASM`), not `STDSW.ASM` or `HIGHSW.ASM`. The PC88VA branch sets `ESCCH=1Bh` and `DOSMES.ASM` selects the existing ESC-letter table. `IBM` is unchanged; no build, VAIO or COMMAND source needed to change.

NEC's *PC-9800シリーズ MS-DOS3.3D ユーザーズガイド*, Appendix D.7, printed p. 205 (PDF page 219), documents **Ctrl-X** to cancel the line without altering the template and **Ctrl-P** to toggle printer echo, with **Ctrl-N** doing the same. Thus PC88VA uses `CANCEL=18h` and `TOGLPRN=FALSE`: despite the old switch comment about separate on/off keys, `CTRLC.ASM` makes `PRINTON` and `PRINTOFF` labels for the same toggle, and the false setting enables the Ctrl-N alias. D.8 on that page lists the template functions. The PDF was extracted and checked in scratch only. Runtime printer echo was **NOT RUN**.

## Build and run

Used FreeDOS-88VA/freedos `66a6acef778ae6aebe5a9d85219788972d6eef9d`, emu2 `9d8698d06e67359bc8b230c2d19d5b1503e60819` and MS-DOS `3d5da84`. In scratch, copy FreeDOS's `experiments/msdos4-va/` to the same relative path, point `components/msdos` and `components/emu2` at the local Git repositories, and set `msdos.commit` in the copied `lock.json` to the full MS-DOS revision. Run the unmodified `python3 experiments/msdos4-va/build.py --output "$OUT"` from scratch with `OUT` an absolute, nonexistent path. The D88 SHA-256 was `5ea7e7e3b798cbacc2ff7e55196237aa7e7b96b5c2fab9ba3323c29dad19919b`.

Used vaeg `Rel.20261118 (m150, 5c2307ac)` with a local VA2 ROM set. From scratch (`REPO` is the MS-DOS checkout), for example:

```sh
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy \
  vaeg --model va2 --no-cfg --no-bkupmem --nowait --roms "$ROMS" \
  --fdd1 "$OUT/msdos4-pc88va-2hd.d88" \
  --headless-input-script "$REPO/docs/J0.2/dir.input" \
  --screenshot 550:boot.png --screenshot 1100:dir-recall.png \
  --screenshot 1800:dir-run.png --screen-tvram-dump dir.tvram
```

Cold boot each script. Use a fresh writable copy of the image for `eof.input`. The scripts use `@key escape` followed by uppercase `@text` (no function-key mapping needed).

## Non-PC88VA comparison

Fresh scratch builds from `release/msdos-va` (`f8cd7e8`) and `3d5da84` used the same builder and tools. In scratch only, set `DEFINES = ()`, remove `-DPC88VA` from bootstrap COMMAND's MASM invocation, and return after `nmake('DOS')` (before BIOS/image work). Both builds completed; the `msdosme.asm` and `msctrlc.asm` commands had no `-DPC88VA`. `cmp` found the two 37,376-byte `tree/v4.0/src/DOS/msdos.sys` files byte-identical (SHA-256 `573626782a3c45f0d9e5f00af1bd0f52a7de44bea96d2a2d3d660e9ae06158d5`).
