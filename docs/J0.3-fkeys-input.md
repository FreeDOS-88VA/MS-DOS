# J0.3 — NEC function keys on CON input

VAIO expands keys from the primitive INT 82h queue (sense `AH=0Ah`, get
`AH=09h`) into CON bytes. It does not use the ROM main input functions,
DefSft expansion, or the JFP. An ordinary byte or the current string byte
can be peeked repeatedly; a read advances it, and a flush drops both cached
input and the remaining primitive queue. Unknown scans still pass through
nonzero internal codes. The B1 interrupt masking is unchanged.

## Table and sources

Checked the *PC-9800シリーズ MS-DOS3.3D ユーザーズガイド* from the local
archive before changing VAIO (PDF extracted only to scratch):

- §2.1, printed p. 13 (PDF 27) uses BS to correct command input. D.7,
  p. 205 (PDF 219) describes Ctrl-H as removing the last character,
  Ctrl-J as a screen-only line break, and Ctrl-X as cancelling the
  command line without changing the template. D.8 on the same page
  matches all ten F-key functions and lists INS as an alias for F8.
- The KEY entry, p. 188 (PDF 202), says that function and cursor-key
  assignments can be set, but does not list their default bytes. The
  arrow navigation in §2.1 pp. 16–17 (PDF 30–31) is for MENU. The DEL
  that deletes *at* the cursor in §7.3 p. 109 (PDF 123) is for SEDIT,
  not COMMAND. Neither is a reason to give COMMAND a forward delete
  or cursor navigation. The guide does not specify alternate command
  line mappings for LEFT, RIGHT, or DEL in the sections checked.
- For byte values and layout, read FreeDOS(98)'s
  [`conkey60.asm`](https://github.com/lpproj/fdkernel/blob/c9ce245e0447003645adce47bd34960ae276d4bd/nec98/kernel/conkey60.asm).
  VAIO uses its own MASM declarations and implementation. As a separate
  check, stripped the sector headers of `DOS33D_1.D88` from the same ZIP,
  located the definitions by their unique labelled F1 payload, and compared
  the strings and labels up to the first NUL with the built IO.SYS.
  **31/31 matched.** To reproduce the comparison, take 10 payloads
  at stride 16 starting at `FEh` in the disk image, skip the next
  five slots, take 10 more, skip five, then take 11 at stride 8.
  Compare those to the built table's 20 at stride 16 and 11 at stride 6.
  The disk representation's length bytes, extra slots, and padding
  are not part of the VAIO table.

No guide-driven change to the listed defaults was needed. The actual
resident layout is 20 × 16 bytes followed by 11 × 6 bytes (386 total), all
NUL-terminated. The optional `FEh` + five-byte label applies to the long
slots and is skipped on input. The table contains:

| VA scan (hex) | Keys | CON payload in slot order |
|---|---|---|
| `62–6B` | F1–F10 | `ESC S/T/U/V/W/E/J/P/Q/Z` with labels `C1 CU CA S1 SU VOID NWL INS REP ^Z` |
| `82–8B` | Shift+F1–F10 | `dir a:` CR, `dir b:` CR, `copy `, `del `, `ren `, `chkdsk a:` CR, `chkdsk b:` CR, `type `, `date` CR, `time` CR |
| `36–39` | ROLL UP/DOWN, INS, DEL | empty, empty, `ESC P`, `ESC D` |
| `3A–3D` | Up, Left, Right, Down | `0B 08 0C 0A` |
| `3E`, `3F`, `AE` | HOME/CLR, HELP, Shift+HOME/CLR | `1A`, empty, `1E` |

The PC-88VA technical manual `603KEYB.TXT` §6.3 (scan/internal-code table,
30h–3Fh) shows Shift arrows at `AA–AD` and Ctrl arrows at `BA–BD`, all
with internal code 0. Both ranges alias the four plain arrow slots; no
extra definitions are added. Shift+HOME/CLR uses its own slot. The Ctrl
column for HOME/CLR is blank; there is no Ctrl slot, and Ctrl+HOME/CLR
produced no byte on VA2. The VA modifier choices are not assertions about
PC-98 modifier behavior.

## Build and run

Built `63db849` (baseline) and `5f1f287` (VAIO change) with the unmodified
FreeDOS-88VA/freedos `experiments/msdos4-va/build.py` from `66a6ace`, using
emu2 `9d8698d`. As in [J0.2](J0.2-line-editor.md#build-and-run), set
`msdos.commit` in each scratch lock and run the builder with a new output
directory. Both builds completed ([VAIO assembly log](J0.3/vaio-build.txt));
MSDOS.SYS and COMMAND.COM were byte-identical by SHA-256. IO.SYS grew from 18,490 to 19,018 bytes; both
sizes still occupy 19 boot sectors. D88 SHA-256:

- Baseline: `edbed441dc1afa5b2b4959f57a73cef093565715550158e1f62dda26f460e005`
- J0.3: `c4fcc9cb49ed37d33d194838b59b887dd324939ff873c4afc33d279bf2527fd3`
- J0.3 plus CONKEY.COM: `6833e3485755fb10481c2b5c0f0c92057e99f71d7765dc3d77d000348d6d6dc5`

Build [`tests/pc88va/CONKEY.ASM`](../tests/pc88va/CONKEY.ASM) with
MASM 5.10 / LINK 3.65 / EXE2BIN, and add `CONKEY.COM` to a scratch copy
of the J0.3 D88. Use the same procedure as for [FKPROBE](J0-probe.md#build-and-run)
(replace the name in the commands and the root entry). [Build log](J0.3/probe-build.txt):
zero MASM errors/warnings, expected LINK L4021 (COM has no stack segment),
345-byte COM, SHA-256 `8df318bd095f7ac19b81c59282a84f0e34c5247be494789a195ee71165a3a31a`.

Counted runs used vaeg PR #82 branch `topic/m153-mov-ss-shadow`,
`Rel.20261121 (m153, 6367e5d3)`, model VA2, local VA2 ROMs, no saved
config or backup RAM. Built it from the branch with CMake/Ninja
`-DCMAKE_BUILD_TYPE=Release -DVAEG_BUILD_TRACK=m153 -DVAEG_ENABLE_RECORDING=OFF -DVAEG_ENABLE_LIBRASHADER=OFF`
(target `vaeg`). Its SHA-256 was
`a3ab65a03eac9fd2abccca3d51b8e464266a4b6141b9d5132b5b667495655906`.
The debug scripts send real guest key make/break events (`key-tap` and
held SHIFT/CTRL), never ESC-letter substitutes. For example, from a fresh
scratch run directory with a writable `disk.d88`:

```sh
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy \
  "$VAEG" --model va2 --no-cfg --no-bkupmem --nowait --roms "$ROMS" \
  --fdd1 disk.d88 --debug-script "$REPO/docs/J0.3/eof.debug" \
  --debug-output-dir . --screen-dump end.png --screen-tvram-dump end.tvram
python3 "$FREEDOS/experiments/msdos4-va/readfile.py" disk.d88 T.TXT | xxd -p
```

Cold boot each script. Use the probe image only for `api`, `edit-bytes`
and `fkey-bytes`; use an unmodified fresh copy of the J0.3 image for every
COPY CON run. `memory.input` and the original `regression.input` use
`--headless-input-script` instead of a debug script, with final screenshots
at frames 1600 and 1450 respectively. Text observations below use vaeg's
`tools/qa/m75_scsi_harness.py` TVRAM decoder and/or screenshots.

Pass counts are checks (not necessarily distinct boots); step 5 counts
cold boots. See the [run observations](J0.3/observations.txt) and
[scripts and captures](J0.3/).

| Step | Result | Evidence |
|---|---|---|
| 1. DIR / F3 / Enter | **1/1** | F3 put `DIR` back at the [prompt](J0.3/dir-recalled.png) (1370); Enter ran the listing and [returned](J0.3/dir-end.png) (2049). |
| 2. Copy/skip from `ABCDEF` | **4/4** | Separate boots: F1 F1 → `AB`, F2 D → `ABC`, F4 F3 → `BCDEF`, F5 D F3 → `DEF`. The initial `ABCDEF` was submitted as a command to seed the template. |
| 3. Insert/replace | **2/2** | F8 and the physical INS key both inserted `X` without advancing the template. After F9, `Y` replaced the template's `A`; F3 completed `XYBCDEF` on both boots. |
| 4. New template / kill | **2/2** | F7 wrote `XYZ` to the template, F1 copied `X`, F6 killed the working line, and F3 still recalled `XYZ` ([captures](J0.3/reedit.png), 935/1100/1329). |
